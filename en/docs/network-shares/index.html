Repositories on a network share

Open a repository on an SMB share, a NAS or a virtual machine.

Git works on a network share, but slowly: a single command can take tens of seconds there. Gitlo adapts to this.

“Different owner” (safe.directory)

For security, git refuses a repository owned by another user, which often happens on a share. Gitlo detects this and offers to add the folder to safe.directory, using the value git suggests. Since this changes your global git config, Gitlo asks you to confirm first.

When opening a repository, Gitlo also recognizes a .git that points to a path on another machine, and a folder it cannot reach. In any other case, it shows git’s message with a Détails (Details) button.

Refreshing

On a UNC path (\\server\share), or when native file watching fails, Gitlo checks only HEAD, refs, the index and the merge state every 2 s. Working copy files are then re-read only when you press F5 or after an action.

Disconnected share

Gitlo never removes a repository from the recent list just because the share is temporarily unreachable. It removes it only if the folder is no longer a git repository.
