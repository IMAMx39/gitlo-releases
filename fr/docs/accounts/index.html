Comptes et hébergeurs

GitHub, GitLab, Gitea, Bitbucket, Azure DevOps et serveurs auto-hébergés.

Connecter un compte

Ouvrez Paramètres › Comptes (Ctrl ,) et collez un jeton d’accès personnel. Gitlo le valide auprès de l’hébergeur, puis l’enregistre dans le trousseau du système : Gestionnaire d’identifiants sous Windows, trousseau sous macOS, libsecret sous Linux.

Gitlo reconnaît tout seul l’hébergeur d’un dépôt d’après l’URL de son distant.

Serveurs d’entreprise et auto-hébergés

Déclarez GitHub Enterprise, un GitLab auto-hébergé ou un Gitea dans Paramètres › Comptes (type et nom d’hôte). Chaque serveur a sa propre session et son propre jeton. gitea.com se déclare comme n’importe quel autre serveur Gitea.

Pas encore pris en charge : un serveur installé dans un sous-dossier (exemple.fr/gitlab/), ou un hôte SSH différent de l’hôte web.

Ce que vous obtenez

  • Pull / merge requests (Ctrl 3) : liste, création, extraction en local (y compris depuis un fork, dans une branche pr/N ou mr/N) et statut CI.
  • CI/CD (Ctrl 4) : runs GitHub Actions, pipelines GitLab et Gitea Actions, avec les jobs et leurs logs en étapes repliables. Vous pouvez relancer ou annuler un run, sauf sur Gitea (lecture seule). La vue se rafraîchit toutes les 10 s tant qu’un run est en cours.
  • Issues : pastille #123 sur les branches liées à une issue, et Nouvelle branche depuis une issue.
  • Avatars des auteurs. Vous pouvez les désactiver : pour les obtenir, Gitlo envoie l’adresse e-mail de l’auteur à l’hébergeur.
  • Clone directement depuis votre compte.
