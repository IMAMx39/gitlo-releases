Dépôts sur un partage réseau

Ouvrir un dépôt sur un partage SMB, un NAS ou une machine virtuelle.

Git fonctionne sur un partage réseau, mais lentement : une simple commande peut y prendre plusieurs dizaines de secondes. Gitlo s’adapte à ces conditions.

« Propriétaire différent » (safe.directory)

Par sécurité, git refuse un dépôt qui appartient à un autre utilisateur, ce qui arrive souvent sur un partage. Gitlo détecte ce cas et propose d’ajouter le dossier à safe.directory, avec la valeur suggérée par git. Comme cela modifie votre configuration git globale, Gitlo vous demande de confirmer.

Gitlo reconnaît aussi, à l’ouverture, un .git qui pointe vers un chemin d’une autre machine et un dossier injoignable. Dans les autres cas, il affiche le message de git avec un bouton Détails.

Rafraîchissement

Sur un chemin UNC (\\serveur\partage), ou si la surveillance native des fichiers échoue, Gitlo vérifie toutes les 2 s uniquement HEAD, les refs, l’index et l’état de merge. Les fichiers de la copie de travail ne sont alors relus que sur F5 ou après une action.

Partage déconnecté

Gitlo ne retire jamais un dépôt de la liste des récents parce que le partage est momentanément inaccessible. Il ne le retire que si le dossier n’est plus un dépôt git.
